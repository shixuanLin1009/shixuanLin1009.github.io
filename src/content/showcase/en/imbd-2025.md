## Background

During long machining runs, cutting heat makes lathe components expand. This **thermal displacement** can account for **40–70%** of the total loss in machining precision. The *IMBD National Smart Manufacturing Big Data Analysis Competition* (hosted by the Ministry of Education) asked teams to predict the lathe's displacement along the X and Z axes from its sensor data.

## Motivation

I treated the task as **multi-horizon forecasting** rather than one-step prediction. Knowing how displacement will evolve over a long window lets an operator plan compensation or cooling ahead of time, instead of reacting after the error appears.

Real forecasting problems mix heterogeneous inputs, and this one does too:

- **Static metadata** that never changes within a run: each run's machining settings (spindle speed, feed and duration for three stages) and its temperature-control mode.
- **Observed time series**: sensor channels PT01–PT13 and TC01–TC08, plus X, Z and spindle motor readings.

How these sources interact is unknown, which makes the problem hard for a single generic model.

## Method

**Data preparation.** The competition provided **56 runs**, one per date, each with its own settings sheet. I re-encoded the settings into static features: stage RPM, feed and duration as continuous values, with missing stages set to 0. The temperature program became a control type (constant, variable or circulation) plus start temperature, end temperature and slope per hour. I then merged each run's time series with its settings.

**Sliding-window samples.** With PyTorch Forecasting's `TimeSeriesDataSet`, each run is cut into overlapping windows: **100 steps of history** (encoder) predict the **next 500 steps** (decoder). Each date is its own group, and the targets are Disp_X and Disp_Z. This produced **53,027 training samples** and 43 validation samples.

**Model.** I used the **Temporal Fusion Transformer (TFT)** (Lim et al., *International Journal of Forecasting*, 2021), which reported 36–69% lower error than Amazon's DeepAR. TFT suits this problem for four reasons:

- **Static covariate encoders** turn each run's machining settings into context vectors that condition the whole forecast.
- **Variable selection networks** pick the most relevant inputs at each time step and show which variables matter.
- **Gated residual networks** can skip unneeded layers, which helps with a small dataset.
- **LSTM layers plus interpretable multi-head attention** capture both short-term and long-range dependencies.

**Hyperparameter search.** Optuna's Tree-structured Parzen Estimator ran **400 trials**. The best setting used hidden size 642, 9 attention heads, dropout 0.17, learning rate 2.7e-4 and gradient clipping 0.01.

**Setup.** The model was trained on Ubuntu 22.04 with an RTX 3090 (24 GB) and Python 3.13, with dependencies managed by `uv`. The code is split into three notebooks: data preparation, training with tuning, and inference.

## Results

Training converged stably (final train loss 4.97, validation loss 8.05). On held-out runs, the 500-step forecasts follow the measured displacement trends closely.

![Forecasts on eight runs: observed (blue) vs. predicted (orange) X and Z displacement over 500 future steps.](/uploads/showcase/imbd-predictions.webp)

**What the model learned.**

- **Static variables:** the run itself (date) mattered most, which is expected with so few runs. It was followed by the **temperature program**: slope, start temperature and control mode.
- **Time-varying variables:** sensor **PT09** dominated the encoder's importance, well ahead of the spindle motor. PT09 is likely close to the spindle, so I suggested **adding cooling near PT09** as the most direct way to cut spindle displacement and improve precision.
- **Worst cases:** the runs with the largest errors mostly had **inconsistent sampling rates**. When the rate varies too much, the model cannot learn the dynamics.
